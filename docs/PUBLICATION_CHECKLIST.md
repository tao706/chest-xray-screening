# 发布候选检查

## 生成方式

`node scripts/prepare-publication.mjs <全新目标目录>` 根据RELEASE_FILES.json白名单复制源码与当前文档，生成RELEASE_MANIFEST.json记录每个文件大小和SHA-256。目标必须位于工程外且不存在，命令不覆盖源工程或旧目标。

这是待复核源码集合，不是承诺包含所有运行材料的即用包。数据库、凭据和权重由使用者分别准备；examples/chest-xrays白名单中的两张CC0图片随源码提供。

## 本次本地关卡

检查实际生成文件及哈希，不只依赖.gitignore。执行发布内容扫描；在候选目录初始化本地Git并暂存白名单文件，使用ci-source-hygiene.mjs核查实际暂存路径；检查文档链接。来源目录中的工作数据保持不变。

## 排除范围

实际.env、模型权重、数据集、真实图片、上传记录、业务导出、日志、运行依赖、虚拟环境、构建产物和历史任务分工不进入候选目录。存在于工作工程不代表可以公开。根目录LICENSE只在其适用范围内生效，第三方材料仍按原条款处理。

## 发布前仍需确认

- 项目维护者查看候选文件，确认没有遗漏的敏感内容或未获授权的第三方代码。
- GitHub账号、仓库名、公开方式与远程地址尚未指定；没有上传任何代码。
- 权重与未获授权图片不公开；README不能承诺源码下载后不准备额外材料就能运行真实分析。
- GitHub首次云端CI未执行，分支保护尚未启用。
- 功能截图或录屏仍需使用授权演示素材。

首次公开前不应仅凭自动扫描通过就认为完成了安全或法律审计。若修改工作源码，应重新生成一个全新候选目录，再复核实际暂存内容。


## 文件指纹与换行

.gitattributes使用 * -text 禁止Git自动转换换行，使发布清单中的SHA-256与实际跟踪文件保持一致。它不修改源码注释，也不隐藏源码差异。清单不包含自身哈希；修改发布文件后需要重新生成。
