# 影像助手审阅草稿（演示版）

## 使用流程

1. 登录后打开“智能助手”，以 `Subject_id` 查询并选择已完成检查。
2. 在“临床信息”中选择已知症状、持续时间、心肺病史及生命体征核对状态。未提供的项目保持“未提供”；不要在聊天问题中输入姓名、证件号、电话等身份信息。
3. 可使用快捷提问获取检查摘要。是否调用外部语言服务受配置控制；未启用临床上下文外发时使用本地规则摘要。
4. 点击“生成审阅草稿”。系统基于现有预测和结构化信息生成四栏草稿，保存到 MySQL。可人工编辑并保存。
5. 勾选人工核对声明后可标记“已人工审阅（演示）”。这不是正式医疗报告；若临床信息发生变化，应重新生成草稿。

## 数据与权限

- 草稿位于 `clinical_review_drafts` 表，以检查和当前登录用户关联；用户只能读取和编辑自己创建的草稿。只读账号不能创建、编辑或标记审阅。
- 已完成的聊天记录仍按账号保存在当前浏览器；换浏览器不会同步。草稿存储在数据库中，刷新后可重新载入。
- 聊天向大模型发送的内容可能包括用户键入的问题。系统不主动附上 `Subject_id`、`Study_id` 或原始胸片，且会遮盖常见标识符格式；不能保证自由文本彻底脱敏，因此禁止输入身份信息。

## 尚未完成的临床前置条件

- 已接入真实14类权重，但尚未完成临床有效性验证；工程自检不能代替临床验证。
- 病例级大模型分析由 `CLINICAL_LLM_ENABLED` 控制，默认关闭；只有真实模型完成临床验证、隐私评估和适用监管评估后，才应由部署人员明确启用。未启用时仍可使用本地规则摘要。
- 草稿模板是工程功能，不是经临床验证的指南或治疗建议。真实使用前须由有资质的医生审核内容、验证误报漏报与适用人群，并进行隐私、安全和适用监管评估。
- “已人工审阅（演示）”只记录当前登录操作员的确认，不代表医师资质核验或正式签发。
