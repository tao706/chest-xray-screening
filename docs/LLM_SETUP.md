# 智能助手配置与实际行为

助手的检索和语言服务编排运行在Express中。影像识别另由FastAPI提供，二者用途不同。

## 本地回答

server/.env使用LLM_PROVIDER=local，或不提供LLM_API_KEY时，使用本地规则和检索资料回答，不需要外部语言服务。已有检查可以提供结构化上下文。

## 可选外部服务

设置LLM_PROVIDER、LLM_API_KEY、LLM_BASE_URL、LLM_MODEL和LLM_TIMEOUT_MS。模型名、可用接口、权限和费用需以实际服务商为准，本项目不保证示例名称长期可用。

服务端请求兼容Chat Completions形式的/chat/completions，当前还发送thinking扩展字段；不同服务商可能不兼容，需要逐一测试，不能宣称支持所有协议兼容服务。

CLINICAL_LLM_ENABLED控制是否允许发送关联的临床上下文，默认false。包含旧mock版本的检查走本地回退。外部请求失败也会回退本地回答。

## 传输

当前先生成完整回答并做规则校验，再发送SSE片段。Vue使用帧缓冲显示，支持停止显示和重新生成。尚未实现上游生成token实时透传，也没有保证断开浏览器请求立即取消上游计算。

## 信息边界

服务端不主动发送原始胸片，发送的是选定的结构化信息和文本。文本脱敏是有限规则，不能保证过滤所有自由文本身份信息。不要在问题或知识库中输入真实身份数据，不要把密钥放进前端或截图。

回答校验是启发式措施，不保证医学正确性。临床决策和正式报告必须由专业人员处理。
